# 圖片

**階段三排版之前打開這一份。** 個人網站的質感有一半在圖，
而最常見的實況是使用者手上沒有能用的圖。這份講的是那種時候怎麼辦。

## 先問清楚他有什麼

三種狀況，處理方式完全不同：

**一、有拍過的好照片。** 直接用。跳到下面的「規格」。

**二、只有隨手拍的生活照。** 挑一張光線最單純的，去背之後放在純色或漸層底上。
去背的做法看 [cutout skill](https://github.com/yazelin) 那條線，
撞色、綠邊、細節保留的坑都在裡面。

**三、完全沒有。** 這是最常見的，也是最容易做錯的。照這個順序處理：

1. **建議他去拍一張。** 一支手機、一面白牆、窗邊的自然光就夠了。
   個人品牌站上有一張真的臉，比任何設計都有用。這句話值得跟他講。
2. 他不想露臉或來不及，**就不要放人像**。改放作品圖、工作現場、
   他做的東西的截圖。個人網站不是一定要有臉。
3. 連作品圖都沒有（例如做的是不能公開的內部系統），**用動效當首屏底**，
   版面選 `editorial.html`。那個版面靠結構撐場面，本來就不吃圖。
4. 需要抽象的紋理或視覺元素，可以生成，
   用 [codex-imagegen](https://github.com/yazelin/codex-imagegen-skill) 這一類的工具。

## 一條紅線

**不要用網路上找來的人物照片假裝是他，不要用圖庫照片假裝是他的作品。**
使用者說「先放個示意圖就好」也一樣。個人品牌站的全部價值在於它是真的，
放一張別人的照片，被認出來的那天損失的不是網站。

生成的圖也一樣：可以當背景紋理、當抽象裝飾，
**不可以生成一張人臉當成他本人**，也不可以生成一張假的作品放進作品區。

## 規格

| 用途 | 寬度 | 格式 | 大小 |
|---|---|---|---|
| 首屏滿版 | 2400px | jpg 或 webp | 400KB 以內 |
| 作品圖 | 1600px | jpg 或 webp | 250KB 以內 |
| 人像 | 1200px | jpg、去背的用 png | 200KB 以內 |
| 社群分享卡 og:image | 1200×630 | jpg 或 png | 300KB 以內 |

**每一張都要縮過再存進 repo。** 原圖動輒五到十 MB，
進了 git 就刪不掉，之後每個 clone 的人都要下載那些。

縮圖指令，兩個工具擇一，多數機器上至少有一個：

```bash
# ImageMagick
magick 原圖.jpg -resize 1600x\> -strip -quality 82 photos/01.jpg

# ffmpeg
ffmpeg -i 原圖.jpg -vf "scale='min(1600,iw)':-2" -q:v 4 photos/01.jpg
```

`-strip` 那一段會拿掉 EXIF。**這件事一定要做**，
手機拍的照片裡有 GPS 座標，直接放上網等於公開他家地址。

## 寫進 HTML

```html
<img src="photos/01.jpg" alt="排車系統改版後的排程畫面" width="2400" height="1600">
```

- **`width` 與 `height` 一定要寫**，不然圖載進來的時候版面會跳。
  寫原始像素尺寸就好，CSS 會處理實際顯示大小。
- **`alt` 寫這張圖裡有什麼**，不要寫「作品一」，也不要重複旁邊已經有的標題。
  純裝飾的圖寫 `alt=""`。
- 首屏那張加 `fetchpriority="high"`，其餘的加 `loading="lazy"`。

## 檢查器會擋的

`tools/check.mjs` 會檢查每一個本機路徑的 `<img>` 檔案是不是真的存在。
選了 `bleed.html` 卻沒放圖，會直接不通過，不會讓破圖上線。
