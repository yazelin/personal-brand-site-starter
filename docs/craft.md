# 中文網頁的排版手法

這一份是問了三個不同模型家族（deepseek、glm、qwen）之後收斂出來的。
**照「幾個家族提到」分成三級**：三個都提到的直接做，過半的當可選，
只有一個提到的當靈感，要自己驗過再用。

問題是這樣問的：純 HTML 加 CSS、系統字、繁體中文、要跑在 GitHub Pages 上，
哪三個具體的手法最能讓網站看起來像真人親手做的。

## 三個家族都提到，直接做

**一、破除置中。** `margin: 0 auto` 是套版感最大的來源。做法二選一：

```css
/* 主欄靠左偏移，右側固定留白 */
.wrap { max-width: 38em; margin-left: clamp(1.5rem, 12vw, 16rem); }

/* 或用不對稱的網格比例，不要 1fr 1fr */
.hero { display: grid; grid-template-columns: minmax(0, 1.15fr) minmax(0, 0.85fr); }
```

`38em` 這個數字有理由：中文一行大約三十八個字，超過眼睛會抓不到下一行。

**欄寬千萬不要用 `ch`。** `ch` 是「0」這個字的寬度，不是一個字的寬度。
18px 的 Noto Sans TC 實測：一個中文字 18px，一個 `0` 只有 10px。
所以 `max-width: 34ch` 排出來是 **18.9 個中文字**，不是三十四個。
寫的人以為在設三十四字，實際拿到不到十九字，而畫面上沒有任何東西會告訴你這件事。

| 寫法 | 一行實際裝得下的中文字 |
|---|---|
| `max-width: 34ch` | 18.9 |
| `max-width: 38em` | 38.0 |
| `max-width: var(--maxw-text)`（38rem）| 約 34（跟著根字級走，不隨元素字級變） |

`1em` 剛好是一個中文字寬，所以要幾個字就寫幾 `em`。
`tools/check.mjs` 會在中文頁面用到 `max-width: 20ch` 以上時提醒你。

**更好的做法是不要自己設。** `templates/base.css` 的 `p` 已經預設收在
`var(--maxw-text)`，要更窄再自己蓋掉。這條預設值加進去之前，repo 裡當時的十八個範例有九個因為沒設上限，
一行跑到五十七到八十一個中文字，全部是靠這一行收回來的。

**二、中文行高要 1.8 到 2.0。** 英文慣用的 1.5 套到中文會擠。
方塊字的密度比拉丁字母高，字面又幾乎填滿字身，行距不夠就糊成一片。

```css
body { line-height: 1.85; }
```

**三、標題不要用負字距。** 這是英文排版的習慣，套到中文是錯的：
全形字本來就沒有側邊空間，再收就會相碰。

```css
h1, h2, h3 { letter-spacing: 0; }   /* 不要寫 -0.01em */
```

想要標題有呼吸感就用**正的**字距，`0.05em` 到 `0.1em`，
那是系統黑體太緊的解法。三個家族在「內文要不要加字距」上有分歧，
所以那一項沒有進這一級。

## 過半提到，可選

**不等距的垂直節奏。** 等距的間距是模板的特徵。
建議的比例是組內 : 段間 : 章節間大約 1 : 6 : 9，或是每個區塊上大下小：

```css
section { padding-block: 8rem 5rem; }   /* 上大下小，視線自然往下走 */
```

**字重對比拉大。** 中文系統字的字重檔位少，層次做不出來的時候，
靠字重與字級的落差撐：大標用 300 細體配很大的字級，或用 900 粗體配緊湊字級，
內文維持 300 到 400。**選一種，不要兩種都用。**

## 只有一個家族提到，當靈感，用之前自己驗

- `writing-mode: vertical-rl` 做直書的落款或邊條。
  **這是中文限定的手法，英文模板做不出來**，成本也極低。
- `text-align: justify; text-justify: inter-ideograph;` 讓中文兩端對齊，
  排起來像印刷品。要注意最後一行與英數字混排的狀況。
- 首屏用 `align-content: end` 把內容壓到畫面下緣，不要垂直置中。
  **這一條有旁證**：`editorial.html` 本來就這樣做，而它是四種版面裡
  在下面那個比對測試中唯一打平的。
- 用偽元素做一塊低透明度的色塊出血到畫面外，打破垂直的方格節奏。
- 字型堆疊把拉丁字體放在中文字體前面，數字與英文會自然混排出另一種質感。

## 怎麼量自己有沒有進步

這是這一份裡最可以重複使用的部分。**不要用自己的眼睛判斷。**

1. 截你的首屏，跟一個真人做的同類站併成左右一張圖。
2. 丟給看得懂圖的模型問**強迫選擇題**：
   「哪一邊比較像專業人士親手做的，而不是套用免費模板？只回左或右，
   再用三十個字講一個具體的視覺理由。」
3. **左右順序要跑正反兩次**，不然量到的是位置偏好。
4. 至少三個不同家族的模型，看收斂。

**理由比票數有用。** 這個方法真正的產出是那句三十字的理由，
它會直接告訴你差在哪。這條線上實際收到的理由是
「非對稱雙欄」「精準字階」「打破常規網格」，這一份的內容就是照那些理由來的。

**這把尺有解析度限制。** 實測跑過五輪，結論很清楚：

- **排版層級的微調它看不見。** 行高從 1.75 調到 1.85、拿掉負字距、
  區塊間距改成上下不等距，票數完全沒動（三輪都是 2:4），
  而且每個模型三輪都投同一邊，代表它們在回答自己的偏好。
- **概念層級的差異它看得很清楚。** 同樣內容、同樣文案、只有設計不同的兩版
  拿去比，有概念的那版拿到五票、沒概念的零票，而且三個模型的理由
  都直接點名概念的具體元素。

所以用法是：**拿它判斷「這個站有沒有一個想法」，不要拿它調字距。**
票數沒動不代表改錯了（那三條排版修正本身是對的），
代表你改的層級不是它在看的層級。那時候該回頭看 `docs/concept.md`。
