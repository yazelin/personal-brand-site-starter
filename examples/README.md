# 範例

四個虛構的人，四種行業。每一份都是跑完整條流程做出來的，
**用這個 repo 做出來的網站就會長這樣**。

開 [index.html](index.html) 可以一次看到四個，或是
[線上版](https://yazelin.github.io/personal-brand-site-starter/examples/)。

| 人 | 行業 | 概念 | 容器 | 重複單元 | 分節 |
|---|---|---|---|---|---|
| 周允中 | 企業內訓講師 | 工程圖說 | 一張圖紙加標題欄 | 件號 M-01 | 圖號 DWG-01…05 |
| 何柏瑋 | 後端與系統可靠性 | 機櫃 | 一片 U 面板加綠燈 | 一台設備 | U01…U05 |
| 林昀真 | 婚禮與人像攝影 | 接觸印樣 | 一格片格加邊碼 | 一格底片 230-014 | FRAME 036A…060 |
| 許亦晴 | 諮商心理師 | 會談紀錄單 | 一列「標籤｜內容」 | 一次會談 | 單號 0001…0005 |

**四個都不屬於 `templates/` 那五種版面，是照概念生出來的。**
那五種是沒有概念時的安全牌。

## 十八個範例，十八種行業

`docs/trades.md` 列了二十個行業，其中十四個有完整範例。
**多數使用者不是軟體工程師**，所以覆蓋率往實體店、教學、專業服務那邊補：

| 人 | 行業 | 概念 | 受眾第一屏就要看到的 |
|---|---|---|---|
| 青田花室 | 花店 | 花材牌 | 電話、時間、地址、今天還剩幾束、來不來得及 |
| 福安早點 | 早餐店 | 蒸籠 | 開門、收攤、電話、地址 |
| 文賢水電 | 水電師傅 | 配電箱 | 跑哪幾區、多久會到、出勤費多少 |
| 和安小動物醫院 | 獸醫 | 分診卡 | 看什麼、值班到幾點、怎麼掛號、現在該不該衝去 |
| 蘇怡文 | 鋼琴老師 | 練習譜 | 程度、一堂多少、在哪上、時段 |
| 曾郁婷 | 助理教授 | 料箱 | 一句人話講清楚研究什麼 |
| 賴宗翰 | 房仲 | 實價登錄明細 | 熟哪一區、成交過什麼、怎麼收費 |
| 莊惠茹 | 記帳士 | 記帳傳票 | 我這種規模你接嗎、多少錢、什麼時候給資料 |

幾個值得看的做法：

- **房仲**把台北市十二區列出來、只有兩個亮著，用版面講「只熟兩區」，
  一句「深耕在地」都沒寫。**水電**用同一招：撥桿合上的是接的、扳下來的是不接的。
- **獸醫**的撕線存根寫「拿不定主意要不要出門，就打電話。問不收錢，我們寧可你問」，
  直接解掉受眾怕被當成小題大作的心理。
- **記帳**明寫「這一頁沒有寫任何節稅的方法」，並解釋為什麼——那比列一堆專業名詞可信。

還沒做的六個：咖啡店、髮廊、家教與補習、教練與訓練、保險與理財、律師與代書。

## 兩種美學，不是一種

前四個是**克制那一族**：單色、文件隱喻、方格、專業。
第五個 `vj.html` 是**表現那一族**：流體鋪滿整個視窗、名字用漸層剪成看畫面的窗、
顆粒與暗角，概念是 CUE 表。

一開始只有克制那一族，四個看起來像同一個模板。
**那是我的品味，不是唯一一種。** 版面骨架 `templates/signal.html` 也是這一路的。

## 重建過一次：概念要管整頁，不是只做首屏

第一版的四個範例只有首屏各有各的樣子，**首屏以下的結構完全相同**
（同一組 `wrap → 標題 → 段落 → 清單`）。四個站看起來就是同一個模板換顏色。
更糟的是當時的比對只截首屏，所以完全沒量到塌掉的那一半。

重建之後每一份都由概念決定容器、重複單元與分節，從第一屏用到頁尾。
**驗收方式也改了：把首屏遮起來，還要看得出這是哪一個站。**

## 這些數字怎麼來的

每一個行業做兩個版本：**文案一字不差，只有版面不同**。
一個是套 `stack.html` 的中性版，一個是照概念做的版本。
兩張首屏截圖併成一張，問三個看得懂圖的模型
（gemma4:31b、kimi-k2.6、qwen3.5:397b）：

> 哪一邊看起來比較像專業人士親手為這個人設計的，而不是套用通用模板？

**左右順序各跑一次。**

重建之後改成比**整頁**縮圖（先前只比首屏，那是當時漏掉問題的原因），
並且在題目裡明講「請看整頁，不要只看第一屏」：

| 行業 | 概念版 : 中性版 |
|---|---|
| 企業內訓講師 | 5 : 1 |
| 後端工程師 | 5 : 0（一票逾時） |
| 攝影師 | 4 : 1 |
| 諮商心理師 | 4 : 1 |
| **合計** | **18 : 3** |

二十四票裡有二十二票回來，其餘逾時。
**模型給的理由開始提到整頁的一致性**：「全頁採工程藍圖格線與規格框線」、
「以 IDE 介面貫穿全站，視覺主題高度統一」、「整頁以會談紀錄單概念設計，
單號、表格與頁碼皆為內容量身訂做」。那正是重建修掉的東西。

方法與已知的限制寫在 `docs/craft.md`，做法寫在 `docs/concept.md`。

## 攝影師那份跑過三輪受眾審查

它是第五階段的示範。跑法在 `skills/05-optimise/SKILL.md`，
角色是「正在籌備婚禮、預算有限、同時比較五六位攝影師的準新娘」。

| 輪次 | 三個模型收斂出的問題 | 做了什麼 |
|---|---|---|
| 一 | 沒有任何價格線索（3/3）、一張照片都沒有（3/3）、作品區只有文字（2/3） | 加了方案與價格區間、每個案例掛相簿連結 |
| 二 | 價格那條解決了（受眾原話：「省去很多來回溝通」）。新問題：深灰字配深黑底看不清楚（3/3） | 調亮次要文字、放大兩個純文字區塊的字級 |
| 三 | 可讀性抱怨明顯減少但沒歸零，剩下的集中在兩個純文字區塊 | 再調一次 |

**沒有解決的是照片，而那不是設計問題。** 攝影師的網站沒有照片，
等於這個目的缺了必要證據；再往下就該回去跟使用者要素材，
而不是繼續調版面。這正是 `skills/05-optimise/SKILL.md` 裡
「必要證據缺了就回去要，不要硬做」那條規則的實例。

範例站不放假照片，所以它停在這裡。真實的使用者做到這一步會補上自己的作品。

### 兩個值得記的發現

**一、設計評分與受眾評分會給出相反的結論。** 同一頁在
「哪一邊比較像親手做的」拿到五比一，在「這個網站對我有沒有用」被三個模型否定。

**二、對比過關不等於看得下去。** 那頁的次要文字算出來 5.16:1，
通過 `tools/check.mjs` 的 4.5:1 門檻，受眾審查連續三屏都說讀不下去。
對比值算的是兩個色碼，算不到字小、背後有格線、整片深色疊在一起。
