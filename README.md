# personal-brand-site-starter

把一個人的話問出來，做成一頁式的個人品牌網站，首屏會流動。

**In short:** paste this repo's URL into your AI coding agent and ask it to follow
`AGENTS.md`. It interviews you, picks a host that matches your actual situation,
builds a one-page personal site with an animated hero, and checks it before you ship.
Docs are in Traditional Chinese. Zero dependencies, zero build step.

## 這是什麼

一份給 AI 代理人照著跑的作業流程。你不用會寫程式，也不用挑技術。

網路上做個人網站的模板很多，問題是換上你的名字之後，它還是一份模板。
這個 repo 的重點在**前面那段訪談**：先問出你到底要讓來的人做哪一件事，
再決定要放什麼、放在哪裡、長什麼樣。

## 怎麼用

打開你在用的 AI 工具（Claude Code、Codex、Gemini CLI、Cursor 都可以），把這段貼進去：

```
請讀 https://github.com/yazelin/personal-brand-site-starter 的 AGENTS.md，
照它的四個階段幫我做個人品牌網站。先訪談我，不要直接開始寫程式。
```

接下來它會問你問題，一次一題。老實回答就好，答不出來的說不知道，它會替你決定。

想要在本機跑得更順的話，先把 repo 抓下來：

```bash
git clone https://github.com/yazelin/personal-brand-site-starter
cd personal-brand-site-starter
```

然後叫你的 AI 讀 `AGENTS.md`。

### 用 Claude Code 的話可以裝成 skill

```bash
git clone https://github.com/yazelin/personal-brand-site-starter ~/personal-brand-site-starter
ln -s ~/personal-brand-site-starter ~/.claude/skills/brand-site
```

之後在任何專案裡打 `/brand-site` 就會叫出來，不用每次貼網址。
兩種用法讀的是同一份 `AGENTS.md`，不會分岔。

## 四個階段

| 階段 | 做什麼 | 產出 |
|---|---|---|
| 一 訪談 | 問出你真正要促成哪一件事，賣東西、接案、作品集、求職，還是一張正式的名片 | `spec/site.yaml` |
| 二 選型 | 依照你的狀況決定放在哪裡，要不要後端，要不要收錢 | spec 的 `hosting` 區塊 |
| 三 建站 | 生出網站，配一種會流動的首屏 | `site/` |
| 四 驗收 | 機器檢查加人眼確認，然後上線 | 一個能用的網址 |
| 五 優化 | 你的潛在客戶審一輪、你自己驗一輪，兩邊都過才停 | 一份發現清單與改動 |

每個階段結束會停下來給你看，不會一路做到底再一次丟給你。

**什麼叫做完：你的潛在客戶覺得這個網站對他有用，而且你自己覺得這是你的網站。**
兩件事同時成立才算。只顧前者，會做出一個轉換率不錯但你不敢拿出去發的站；
只顧後者，會做出一個你很滿意但沒有人聯絡的站。

**第五階段是這條線最不一樣的地方。** 它不問「好不好看」，
它假扮成你想打動的那個人（要找攝影師的準新娘、正在比三家的資訊主管、
在看履歷的主管），逐屏看過你的網站，然後回答三件事：
看五秒之後他認為你是做什麼的、有沒有哪裡讓他不敢聯絡你、他想知道但你沒寫的三件事。

實測抓到的東西是這種的：「我預算有限，怕太貴不敢問，浪費彼此時間」、
「整頁沒有一張照片，我不知道你拍出來什麼樣子，不敢點聯絡」。
**這些是機械檢查抓不到、設計評分也抓不到的。**

同一圈也會回頭問你四題：有沒有哪一句你唸出來會卡、有沒有哪一句是我替你寫的
而不是你講過的、你現在敢不敢把網址貼給客戶、這一圈改的有沒有哪一項你其實不想要。
**你的潛在客戶說缺的東西，你可能是刻意不放的。那時候聽你的。**

## 五種版面

**結構不一樣，不只是換顏色。** [線上一次比較](https://yazelin.github.io/personal-brand-site-starter/templates/preview.html)。

- **堆疊** 吸頂導覽、靠左首屏、區塊上下堆疊。最通用，判斷不出來就用這個。
- **左右分屏** 首屏左字右動效，內容區左邊黏著標題右邊捲動。雜誌感最強。
- **編號索引** 每個區塊掛一個大編號，字級對比拉到最大。內容少的人用這個最划算。
- **滿版出血** 圖片鋪滿寬度，文字疊在上面。手上有好圖的人才選。

還有第五種**工控面板**，是「概念驅動」的示範：黑黃警示斜紋、粗框、直排側標、工單編號。
它跟同樣內容的中性版對打，三個視覺模型投它五比零。它不是給所有人用的版面，
是拿來看「一個概念怎麼變成版面」。

版面決定於內容有多少、有沒有圖，不是決定於好不好看。前四種各自可以再套四種風格。

## 四種風格

寫在 `<html data-vibe="...">` 一個字就換整站氣質。

- `calm` 克制：淺底、細字、大量留白。求職、顧問、專業服務。
- `bold` 明確：深底、大字、一個亮色。賣東西、接案。
- `gallery` 作品優先：介面退到最淡，圖片佔滿。設計、攝影、影像。
- `grand` 大氣：墨底、襯線大標、金屬色、超大留白。講者、顧問。

## 五種會流動的首屏

`hero/` 底下五支，各自獨立一個檔案。
[線上一次看到五種在動](https://yazelin.github.io/personal-brand-site-starter/hero/preview.html)，
或是在本機開 `hero/preview.html`。

- **流體漸層** 色塊疊加後模糊，緩慢流動。最省效能，也最搶眼。
- **粒子場** 點漂移並連線，滑鼠經過會推開。技術感重。
- **噪聲線條** 一疊橫線緩緩起伏，像等高線。最安靜。
- **幾何緩動** 大型線稿圖形極慢地漂移，像一張會呼吸的海報。
- **流體墨彩** 游標攪動、點一下潑灑的流體，沒人動的時候自己流。最有存在感，也最重。

前四支是零依賴的手寫效果，幾十行，參數開在檔案最上面，AI 會照你的內容調過再用。
第五支是移植過來的 Navier-Stokes 求解器，只調參數不用讀內容，
出處與授權寫在 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

五支都做好了三件事：跟著系統設定關掉動畫、分頁切走停止運算、高解析螢幕不糊。
五種都不對的時候，`docs/effects.md` 會帶你去 90 個開源特效裡挑，
並且說明怎麼包成同一套介面。

## 你的話不會在過程中被改掉

訪談的時候會另外抄一份 `site/voice.txt`，一行一句，是你自己講出來的話。
優化跑到第三圈的時候，你講得最好的那幾句很容易已經被改成通用的行銷語言，
所以那份是護欄：

```bash
node tools/voice.mjs site/index.html site/voice.txt
```

少了哪一句就不通過。實測會被抓到的是這種替換：把
「不擺拍，不喊口號，站在會發生事情的那個位置等」
改成「在最佳位置捕捉每個動人瞬間」。第二句什麼都對，就是誰都可以講。

## 為什麼要有第五階段

同一個攝影師頁面，兩種評法給出相反的結論：

- 用設計角度問「哪一邊比較像親手做的」，它拿到五比一的好成績。
- 用潛在客戶角度問「這個網站對我有沒有用」，三個模型一致說它做不到它的工作。

**只做設計評分，會得到一個好看但沒有人聯絡的網站。**

還有一個實例：那頁的次要文字算出來是 5.16:1，通過無障礙的 4.5:1 門檻，
但受眾審查連續三屏都說讀不下去。對比值算兩個色碼，
算不到字小、背後有格線、整片深色疊在一起。

## 檢查

```bash
node tools/check.mjs site/index.html
```

擋的是幾種一定會被抓包的錯：模板的示範內容忘了換、搜尋引擎與社群分享要的標籤沒寫、
會動的東西沒辦法關掉、圖片檔案不存在、正體中文的頁面混進簡體字、
內文與按鈕的顏色對比低於 4.5:1。通過回傳 0。

後面那幾條是實測出來的：用非 Claude 的模型跑這條流程，它會把「根據」「必須」寫成簡體；
換上自己的品牌色之後按鈕的字看不見，也是常見的翻車方式。好不好看它不管，那要你自己看，清單在 `skills/04-verify/SKILL.md`。

## 參考哪些站

AI 問你風格的時候，**第一個給你看的是這個 repo 自己的十六種組合**，
因為那些是你真的會拿到的東西。看得到的東西問得出意見，形容詞問不出來。

之後才看外面的站，而且挑的是普通專業人士做的、這個 repo 做得出來的那些，
清單在 `docs/inspiration.md`。得獎作品被放在另一個小節，
標題是「使用者說我要做成那樣的時候」，附上該怎麼回應。

**看到做不到的東西，會對做得到的東西失望。** 順序反過來整個流程都會歪掉。

## 五種版面是安全牌，不是天花板

訪談問出概念之後，這條線會**用概念生一個新版面**，而不是從五種裡挑。
`examples/` 裡那四個都是生出來的，沒有一個屬於那五種：

- 講師：一張一張的工程圖紙，件號表、標註、每張自己的標題欄
- 後端：一片一片的機櫃面板，U01 到 U05，每片一顆會呼吸的綠燈
- 攝影：一格一格的底片片格，作品排成印樣網格，帶邊碼
- 諮商：一張長表單，欄位標籤在左內容在右，最後有簽名欄

做法是三個問題：容器長什麼樣、重複的單元是什麼、怎麼分節。寫在 `docs/concept.md`。

## 做出來會長什麼樣

四個行業的完整範例在 `examples/`，
[線上可以直接看](https://yazelin.github.io/personal-brand-site-starter/examples/)：
企業內訓講師（工程圖說）、後端工程師（機櫃）、婚禮攝影師（接觸印樣）、
諮商心理師（會談紀錄單）。四份都是零依賴的單一 HTML，沒有框架也沒有圖片。

## 一個屬於你的概念

版面乾淨、字級有階層、留白正確，做完之後仍然可能被說「看起來像模板」。
缺的通常是**一個屬於你的想法**。

[musicalwebdev.com](https://musicalwebdev.com/) 那個站的概念是百老匯的節目單，
而它沒有用 WebGL、沒有用 canvas，全部是普通 CSS 的旋轉、粗框、直排文字。
它比多數精緻的模板更像人做的。

所以訪談的最後會問你一題：**你這一行有沒有一個東西，別人一看就知道是你們在做的。**
攝影是接觸印樣，講師是工程圖說，後端是機櫃，諮商是會談紀錄單。
答得出來，AI 會把它變成三個具體的版面決定；答不出來就跳過，做乾淨的版面就好。

**這一步有實測撐著。** 五個行業各做兩版，文案一字不差、只有版面不同，
拿去問三個看得懂圖的模型「哪一邊比較像親手為這個人設計的」，
左右順序各跑一次：**概念版二十三票、中性版五票，五個行業全贏。**
做法在 `docs/concept.md`，成品在 `examples/`。

## 沒有做的事

沒有 build step，沒有 npm install，沒有框架。
產出就是可以直接丟上任何靜態空間的 HTML、CSS 跟一支 JS。

要用自己去裝，AI 不會替你安裝任何東西。
