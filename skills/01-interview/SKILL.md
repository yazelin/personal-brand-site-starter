# 階段一：訪談

目標是問出一句話：**這個網站要讓來的人做哪一件事。**
問不出這句話就不要往下走。沒有這句話的網站，做出來只是一份好看的自我介紹，
放三個月沒人聯絡他，他會覺得是網站沒用。

## 怎麼問

**一次只問一題，等他回答再問下一題。** 一口氣丟十個問題，他會挑好回答的答、
跳過真正重要的。這是整個階段最容易做壞的地方。

**判準寫成可以自己檢查的形式：你送出的訊息裡只能有一個問號。**
寫完數一次，超過一個就把多的刪掉，留最重要的那一個。

括號裡的補充說明不要寫成問句。「（例如你希望對方用什麼方式找你？）」
這種也算一個問號，改成「（例如：表單、寄信、預約時段）」。

這件事實測過會破功：模擬一場十四輪的訪談，有八輪違規，最嚴重的一輪問了五個問題。
會破功是因為有些題目天生想一次問完（風格、顏色、概念常常被綁在一起問）。
**數問號比記規則有效。**

**用選項問，不要用開放題問。** 「你想要什麼風格」他答不出來。
「安靜克制像一份履歷，還是強烈一點像一張海報」他答得出來。

**他說不知道的，你替他選，講一句理由，繼續往下。** 不要停在那裡等他想。
模擬跑下來，「我沒想過耶」是最常出現的回答之一，那是正常的，不是他不配合。

**他堅持要放很多東西的時候，不要當場說服他。** 有些人會說
「家長就是想看這些，有人建議我精簡我還不高興」。當場爭辯只會讓他關掉對話。
正確的做法是照他說的先做出來，到階段五讓他的受眾去講——
那時候是他的潛在客戶在給意見，不是你在跟他吵。

## 第一題永遠是這題

> 這個網站做出來，你最希望來的人做哪一件事？
>
> A 直接買你賣的東西
> B 寄信或加你聯絡，談合作或接案
> C 看完你的作品，記住你是誰
> D 看完願意找你面試
> E 有個正式的地方可以放在名片和簽名檔

他的答案決定後面問什麼。他答不出來，就問他「上次有人透過網路找你，是為了什麼事」，
用那件事往回推。

## 各路線的必問清單

問完共通題，再問路線題。共通題四個，路線題三到五個，總共不要超過十二題。

### 共通（每條路線都要問）

**下面每一條就是一輪，不要合併。** 這份清單原本有幾條寫成「甲，以及乙」，
實測代理人就照著一次問兩題——**題目本身是複合題的時候，規則擋不住。**

1. 你希望別人怎麼稱呼你？
2. 用一句話說，你是做什麼的？
3. 這個站的訪客大部分會是誰？（決定用詞深淺，也決定要不要解釋術語）
4. 你手上現成有哪些素材？（照片、作品圖、logo、社群或作品連結，有哪些說哪些）
5. **有沒有什麼是你看到會覺得「我絕對不要這樣」的？**
   舉兩個例子讓他好答：「像購物網站那樣一格一格標價錢」「像那種很浮誇的網紅頁面」。
6. 有沒有買過網址？就是像 `abc.com` 那種、打進去就會到你網站的名字。
   沒有也沒關係，這題現在不用決定。

**第五題每一個人都答得出來，而且答案很強烈。** 模擬三個不同行業的使用者，
三個都主動講了「不要像購物網站」「不喜歡那種很商業化的感覺，太像補習班廣告」
這類的話——**問了才會早點知道，沒問就會做到一半才被打回票。**
他的回答要原話抄進 `spec` 的 `avoid`，後面每一個階段都要對照。

第六題不要講「網域」兩個字。實測有使用者直接回「那個 yourname.com 是要自己花錢買的嗎」，
再往下問就會變成技術問答，訪談就歪了。

### A 賣東西

1. 你賣的是什麼？
2. 賣多少錢？
3. 一次性還是訂閱？
4. 買了之後怎麼交付？（檔案下載、寄信、開通帳號、線下服務）
5. 現在收錢用什麼？（沒有的話，選型階段會替他決定）
6. 有沒有人買過？（有的話再問他們說過什麼。沒有就不要在站上假裝有）
7. 退款怎麼處理？

### B 接案

1. 你接哪一類案子？
2. 有沒有哪一類是你不接的？**「不接什麼」比「接什麼」更能篩掉爛詢問。**
3. 從聯絡到交件，大概是哪幾步？
4. 一件大概要多久？
5. 預算帶大概在哪？（願意寫的話，能擋掉一半不合的詢問）
6. 希望對方用什麼方式找你？（表單、寄信、預約時段）

### C 作品集

1. 挑三到六件最想被看到的作品，是哪幾件？
2. 每一件難在哪？（一件一件問，不要一次要他講完）
3. 每一件你負責的是哪一段？（合作案要寫清楚，不然像是全部你做的）
4. 有沒有不能公開的案子？**這題一定要問**，做完才發現不能放會很麻煩。

### D 求職

1. 想投什麼職位？
2. 什麼產業？
3. 三件最能代表你能力的事，是哪三件？（每件要有可以驗證的結果）
4. 履歷 PDF 要不要放在站上讓人下載？
5. 現在的求職狀態要不要公開寫？（在職中的人通常不能寫）

### E 名片

1. 要放哪些聯絡方式？
2. 要放哪些社群？
3. 要不要放近況區塊（在做什麼、最近寫了什麼）？
   **選不更新的話，站上不要出現任何日期。** 一個掛著去年日期的站比沒有站更傷。

### 收尾的時候不要打包

問到最後會剩幾個零星的小問題（城市、Email、社群網址）。
**實測代理人會把它們編號成一張清單一次問完**，那一輪就有四個問號。
零星的問題也是一次一個，或是你自己判斷得出來的就直接替他決定，
在交 spec 的時候一起講。

## 風格只問這兩題

問完內容再問風格，順序不要反過來。內容決定風格，反過來會做出一個裝不下內容的殼。

**先把版面預覽給他看**，那裡是五種版面乘以四種風格，都是他真的會拿到的東西。

**給他線上網址，不要叫他打開資料夾雙擊檔案。**
https://yazelin.github.io/personal-brand-site-starter/templates/preview.html
實測有代理人叫一個說「GitHub 我聽不懂那是什麼」的使用者去開本機檔案，
那是不必要的門檻。範例站也一樣：
https://yazelin.github.io/personal-brand-site-starter/examples/看得到的東西問得出意見，形容詞問不出來。

**不要一開始就丟外面的得獎作品給他看。** 看到做不到的東西，
會對做得到的東西失望，接下來整個流程都會歪掉。

他挑完之後，再打開 `docs/inspiration.md`，照那份的第二步去
personalsit.es 篩他那一行，找兩三個同行的站補充討論。
他指了一個之後追問「像在哪裡」，那句回答就是設計決策。

然後才問這兩題：

1. 給他看三個方向，挑一個：
   - **克制**：淺底、細字、大量留白、幾乎沒有顏色。適合求職、顧問、專業服務。
   - **明確**：深底、大字、一個強調色。適合賣東西、接案。
   - **作品優先**：介面退到最淡，圖片佔滿。適合設計、攝影、影像。
2. 有沒有一定要用的顏色，例如既有的品牌色或 logo 顏色。沒有就由你配。

第四個方向是 `grand` 大氣：墨底、襯線大標、金屬色、超大留白。
講者、顧問、或是想要沉穩恢弘那一路的人適合，判斷不出來的時候不要主動提，
他自己講出「氣派」「大器」「有份量」這類詞再拿出來。

## 最後問這一題

風格問完之後問這一題，它比前面所有風格題加起來更決定成品像不像他：

> 你這一行有沒有一個東西，別人一看就知道是你們在做的？

一個物件、一張表、一個場景都可以。舉例的時候**不要把例子寫成問句**，
實測有代理人寫「可能是裁皮刀、縫線的特寫、或是工作檯的樣子？你有沒有想到什麼？」，
那一輪就有兩個問號。改成陳述句列出來就好。

**問之前先打開 `docs/concept.md`**。那裡有已經問出來的五個行業的概念可以拿來提示他
（工廠控制台、工程圖說、機櫃、接觸印樣、會談紀錄單），
還有為什麼這一題重要：五個行業的實測，有概念的版本對上文案一字不差的中性版，
是二十三票對五票，每一個行業都贏。

成品在 `examples/`，可以直接開給他看「會做成什麼樣子」。

答不出來就跳過，不要硬掰。**沒有概念的乾淨版面，比有一個牽強概念的版面好得多。**

## 首屏動效不用問

首屏動效不要問他要哪一種，四種效果的取捨在 `skills/03-build/SKILL.md`，
你照他選的方向配一種，做出來給他看，他不喜歡再換。**看得到的東西才問得出意見。**

## 材料不夠就不要產出

實測時我故意在訪談還沒開始的情況下，直接叫代理人輸出 `spec` 與 `voice.txt`。
兩個不同家族的模型都拒絕了，而且理由是對的：

> 這兩份檔案我現在生不出來。spec 裡的每一句文案、voice.txt 的每一行，
> 都必須是你自己講過的話，逐字抄、不能由我發明。我如果現在憑空寫出你的名字、
> 你的定位、你的目標受眾，那就是我編的一個假的你。

**這個行為是對的，保持它。** 使用者中途說「你直接生一份給我看」也一樣，
沒有材料就講清楚少了什麼，回去問。**空著比編一個好。**

## 產出

寫成 `spec/site.yaml`。**下面這些欄位一個都不能少**，
不要自己發明結構——實測有代理人自創了一套 schema，
把 `tagline`、`lede`、`facts`、`avoid` 全丟了，後面的階段就接不上。

```yaml
goal:        # buy | contact | remember | hire | card
one_line:    # 這個網站要讓來的人做哪一件事，一句話
person:
  name:
  title:
  tagline:   # 首屏大標，他自己的話
  lede:      # 副標，他自己的話
  location:
  email:
  links: [{label:, url:}]
audience:    # 一個具體的人，有處境跟顧慮，階段五要拿它當角色
avoid:       # 他明講絕對不要的東西，抄原話，一行一條
style:
  vibe:      # calm | bold | gallery | grand
  layout:    # stack | split | editorial | bleed
  hero:      # noiseLines | flowGradient | particleField | geoDrift | fluidInk
  brand_color:
  concept:   # 問得出來才寫
sections: []  # 用得到的才留
offer: []     # 有賣東西才寫
work: []      # 有作品才寫
faq: []
hosting:
  platform: # 階段二填
  domain:
  backend:
  payment:
```

完整的範例在 `spec/site.example.yaml`，**開起來對一次再交出去**。
寫完跑 `node tools/spec-check.mjs spec/site.yaml` 驗一次。

**訪談被打斷的時候不要硬填。** 實測有一場對話中途斷掉，代理人就拿
「一件一件做的」當 `tagline`、「公事包、皮夾這種」當 `lede`——
兩句都是他講的沒錯，但那是半句，不是一句話。
`spec-check` 會對太短的欄位提醒，看到就回去把那一題問完。
寫完把 `goal`、`audience`、`sections` 三段唸給他聽，確認過再進階段二。

寫進 spec 的每一句文案都要是他自己講過的話，只做刪修，不要替他發明。
你替他寫的漂亮句子，他之後唸給客戶聽會卡住。

**另外開一個 `site/voice.txt`，一行一句，把他自己講出來、你決定要放上網站的話抄進去。**
那份是後面優化階段的護欄：跑到第三圈的時候，他講得最好的那幾句常常已經被改光了，
`node tools/voice.mjs site/index.html site/voice.txt` 會抓出來。

抄進去的判準是「這句話換成別人講就不成立」。

**voice.txt 要逐字抄，不要濃縮、不要合併兩句、不要改寫。**
實測四個代理人裡有一個把十三句裡的七句改寫過，那樣等於這份護欄失效——
它本來就是拿來擋改寫的。

抄完自己驗一次：**每一行都要能在對話紀錄裡原字找到。** 找不到就是你改過了。

另外兩個實測踩到的：有代理人把自己的流程標記（像 `[訪談完成]`）
跟 markdown 的圍籬也抄進去了；模型輸出常見的繁簡轉換錯字
（「不是隻為了應付考試」的「隻」）要順手改掉，**但語氣一個字都不要動**。
像「不擺拍，不喊口號，站在會發生事情的那個位置等」這種，
換成「在最佳位置捕捉每個動人瞬間」就完全沒有他了。
